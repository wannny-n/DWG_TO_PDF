# План бесплатного автономного DWG -> PDF

## Принятое решение

Основной контур: `DWG -> ODA File Converter -> DXF -> ezdxf/PyMuPDF -> PDF`.
Он не запускает nanoCAD, не использует COM и не зависит от виртуального
принтера. Исходный DWG открывается только для чтения, промежуточный DXF живёт
во временной папке и удаляется после обработки файла.

## Реализовано

1. Выбор отдельных DWG и папок, рекурсивный поиск, исключение дубликатов и
   последовательная очередь.
2. Один DWG создаёт один многостраничный PDF; несколько успешных PDF можно
   собрать в один файл с закладками на DWG.
3. Layout берёт размер и ориентацию страницы из page setup DWG.
4. В ModelSpace распознаются именованные рамки A0--A4; масштаб модели не
   влияет на формат итоговой страницы.
5. Рендеринг векторный. Сущности вне выбранной рамки отсекаются до рендеринга,
   что ускоряет альбомы с большим количеством листов.
6. Приложенный TTF регистрируется до создания CAD-контекста: кириллица ГОСТ
   выводится шрифтом, а не квадратами.
7. Текст из `TEXT`, `MTEXT` и вставленных блоков добавляется как скрытый
   Unicode-слой у исходных координат. Работают поиск и выделение текста.
8. После создания проверяются сигнатура PDF, число страниц и извлечение
   текста.

## Приёмка перед использованием на новом архиве

1. Передать исходные TTF/SHX всех корпоративных стилей, не только GOST.
2. Экспортировать 1--3 характерных листа каждого типа (Layout, рамки
   ModelSpace, сложная графика).
3. Сверить формат, линии, заливки, шрифты и поиск с эталонным PDF/CAD.
4. Только после такой сверки запускать всю папку и передавать общий PDF.

Это условие необходимо для честного требования `1:1`: свободный DXF-конвертер
не может гарантировать идентичность нераскрытых proxy-объектов, Xref и
отсутствующих CAD-шрифтов.
