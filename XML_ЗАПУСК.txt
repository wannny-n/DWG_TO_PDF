Пакетный запуск DWG → PDF с XML-заданием

Скопируйте example-job.xml и замените примеры путей своими. Передайте XML
единственным аргументом EXE; флаг --batch в этом случае не нужен.

$p = Start-Process -FilePath ".\DWG_Sheet_Scanner.exe" `
    -ArgumentList '"C:\Задания\job.xml"' -Wait -PassThru
$p.ExitCode

Окно приложения не открывается. Программа сохраняет вывод в conversion.log.
Для обычного запуска с интерфейсом откройте EXE без аргументов.

Формат XML (UTF-8), корневой тег <DwgToPdf version="1">:

  Sources — обязательно. Один или несколько File (DWG) и Folder (папка).
    Очередь следует порядку тегов; внутри папок файлы ищутся рекурсивно
    и сортируются по нумерации. Повторы одного файла исключаются.
    У File можно задать sheets="1,3,5" — позиции листов из окна выбора,
    начиная с 1. Порядок номеров задаёт порядок страниц. Без sheets — все листы.
  OutputDir — обязательно. Каталог PDF и отчётов.
  Merge — общий PDF; по умолчанию true. При false — отдельные PDF.
  CombinedPdf — путь к общему PDF, если Merge включён. По умолчанию
    DWG_Combined_autonomous.pdf. Относительный путь считается от OutputDir.
  IncludeModelFrames — печать рамок модели, по умолчанию true.
  IncludeLayouts — печать листов Layout, по умолчанию true.
  Oda — путь к ODAFileConverter.exe. Если не задан, используется обычный
    поиск ODA, включая папку ODA рядом с EXE.
  Fonts — необязательный список тегов Font с путями к TTF, OTF или SHX.
    Если список пуст, используется комплектный GOST2304A.ttf.
  Overwrite — разрешение заменить PDF с тем же именем, по умолчанию false.
    При false к занятому имени добавляется _2, _3 и т. д.

Все остальные относительные пути считаются от папки XML-файла.
Логические значения: true / false (также 1 / 0). XML не использует DTD.

Код завершения:
  0 — конвертация завершена без ошибок; возможны предупреждения.
  1 — ошибка выполнения или не удалось преобразовать часть DWG.
  2 — неверное XML-задание или DWG не найдены.

Файлы conversion.log, headless_batch_progress.json и headless_batch_report.json
находятся в OutputDir (отчёты появляются по мере обработки). При ошибке
чтения или проверки XML подробности пишутся рядом с заданием в job.error.log,
если папка доступна для записи. У каждого параллельного задания должен быть
свой OutputDir, чтобы журналы и отчёты не перезаписывали друг друга.
